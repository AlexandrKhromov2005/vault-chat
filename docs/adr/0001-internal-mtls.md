# ADR 0001: взаимная аутентификация внутренних RPC

Статус: принято. Дата: 2026-10-22.

## Контекст

Приватная сеть Docker ограничивает внешний доступ, но plaintext gRPC не
удостоверяет сервис. Компрометация одного контейнера не должна автоматически
давать право на любой RPC другого сервиса.

## Решение

Прямой gRPC с TLS 1.3 и private CA для каждого развёртывания. У каждого сервиса
свой leaf с DNS SAN и точным service URI; клиент проверяет целевой сервис,
сервер — CA и идентичность клиента. Unary/stream interceptors ограничивают
методы по матрице из [инструкции mTLS](../mtls.md), default deny.
Авторизация пользователей через JWT/членство сохраняется.

Используем стандартные crypto/tls и gRPC credentials. Service mesh пока не нужен
для четырёх сервисов одного VPS. Общий сертификат для всех сервисов не выбран:
он не позволил бы ограничить RPC по вызывающему сервису. Signing key CA не
монтируется ни в один runtime-контейнер.

## Последствия

Требуются выпуск, мониторинг срока и ротация сертификатов. Leaf-ротация с тем же
CA реализована с перезапуском и коротким перерывом; автоматического отката к
plaintext нет. Local plaintext остаётся для совместимости локальной разработки;
VPS явно включает защищённый overlay, который сохраняется в backup.
Нет CRL/OCSP: при компрометации нужен новый CA и перезапуск всего стека.
Защита Redis/БД/S3 и независимый secret manager остаются отдельными задачами.

Проверки: реальные отрицательные TLS handshakes, RPC ACL (включая streams),
пользовательские сценарии и смена leaf-ключей с сохранением CA и данных.
