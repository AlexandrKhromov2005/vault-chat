## [0.2.0] — 2026-10-22

### Добавлено

- Gateway отдаёт веб-клиент на `http://localhost:8080/` со строгим CSP без
  `unsafe-inline`; клиент встроен в бинарник Gateway.
- В веб-клиенте: регистрация, вход и выход; токены в `sessionStorage` вкладки
  обновляются до истечения и после `401`.
- В веб-клиенте: список комнат пользователя, поиск пользователей с открытием
  личного диалога и создание каналов.
- В веб-клиенте: переписка с историей, подгрузкой и безопасным повтором
  отправки.
- В веб-клиенте: панель участников; владелец канала добавляет и удаляет
  участников, остальные могут покинуть канал.
- В веб-клиенте: загрузка вложений в комнату, отправка их с сообщением и
  скачивание.
- В веб-клиенте: события в реальном времени по WebSocket с индикатором
  соединения и отметками новых сообщений; после обрыва клиент
  переподключается с нарастающей задержкой и пересинхронизирует комнаты.
- Сценарий демонстрации в `docs/demo.md` и переменная `AUTH_JWT_ACCESS_TTL` в
  Compose для показа обновления токена.
- `xmake ci` — все проверки одной командой: формат, vet, lint, сборка, тесты с
  race detector и integration-тестами PostgreSQL и S3, покрытие, фаззинг и
  `govulncheck`. `xmake setup` ставит pre-commit хук с быстрыми проверками.

- VPS: отдельный Compose с закрытыми хранилищами, HTTPS по IP, системными
  таймерами продления сертификата и резервного копирования. Команды установки,
  обновления и восстановления в новый проект сохраняют секреты и проверяют
  целостность копий; проверки включены в `xmake ci`.

### Исправлено

- Go обновлён до 1.27.3: в 1.27.2 была достижима уязвимость GO-2026-6809 в
  `crypto/x509` стандартной библиотеки.
- Rate limiter Gateway сразу пропускает запрос, если Redis недоступен: без
  повторных подключений и повторов команд. Раньше остановленный Redis
  задерживал каждый запрос на секунды, а отправка сообщения могла получить `504`.

## [0.1.0] — 2026-10-17

Первый релиз backend MVP. Auth, Chat, Media и Gateway запускаются через Docker
Compose с тремя отдельными PostgreSQL, Redis и закрытым S3-хранилищем.

### Возможности

- Регистрация, вход, Argon2id, JWT RS256, ротация refresh token, отзыв сессий.
- Публичные профили и поиск пользователей по началу имени.
- Личные диалоги и каналы, список комнат, управление участниками и проверка доступа.
- Сообщения с защитой от дубликатов, история с курсором, catch-up и WebSocket-события.
- Закрытые вложения до 10 МиБ: загрузка и скачивание с проверкой текущего членства,
  проверка типа содержимого, ссылки на файлы в сообщениях, истории и live-событиях.
- REST Gateway, rate limit, CORS, ограничения тела и времени запроса,
  опциональный публичный TLS, JSON-логи, request ID и health endpoints.
- Миграции, unit/race, fuzz, PostgreSQL/S3 integration и сквозные Compose-тесты.

### Проверки

На коде релиза прошли unit/race, vet, golangci-lint, protobuf lint, сборка,
фаззинг, интеграционные проверки PostgreSQL/S3 и сквозной сценарий через Compose.
При проверке govulncheck достижимых уязвимостей не найдено. В модуле `x/crypto`
есть advisory для неиспользуемого приложением пакета OpenPGP.

### Ограничения

- Веб-клиента нет; взаимодействие доступно через REST и WebSocket.
- Внутренний gRPC работает без TLS; mTLS и production-управление секретами впереди.
- Redis Pub/Sub не сохраняет события; сообщения восстанавливаются через catch-up.
- Кэш данных приложения, метрики, дашборды и алерты пока не реализованы.
- MinIO собирается из закреплённого исходного кода для разработки. Перед production
  нужен поддерживаемый S3-провайдер. Антивирус, квоты и retention файлов не реализованы.
- Уже выданный access token действует до истечения срока после отзыва сессии.
