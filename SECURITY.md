# Security policy

Report vulnerabilities privately using
[GitHub private vulnerability reporting](https://github.com/AlexandrKhromov2005/vault-chat/security/advisories/new).
Do not include exploit details, credentials or personal data in public issues.

Include the affected commit/version, impact, a minimal reproduction using synthetic
data, and any proposed mitigation. Do not send private keys or production dumps.

Security fixes target `main`. Older commits are not separately maintained; users
should update to a reviewed version containing the fix. Response and release times
depend on maintainer availability; there is no guaranteed response SLA.

Development controls and their limitations are described in
[secure development](docs/security-development.md). Deployment requirements,
including external encrypted backups, are in [deployment](docs/deployment.md).
